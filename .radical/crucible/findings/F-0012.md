## Steps

1. POST /events {id: 370113 (a number), type:'order.paid', orderId:'X'}  → 200, recorded
2. POST /events {id: '370113' (a string), same type and orderId}  → 200, recorded again
3. GET /notifications?orderId=X lists 2

## What differs

```text
Expected: a 4xx for the numeric id; otherwise one notification for X
Actual: two notifications for one event, eventId 370113 and eventId '370113'
Seen: 2 of 2
Where it probably comes from: services/notifications/src/notifier.ts handle(): the Map is keyed on event.id, so 370113 and '370113' are different keys (guess: no id type check in server.ts line 10)
A test that would catch it: services/notifications: an event whose id is not a string is refused with a 4xx; a repeat of an event id is recorded once
```
