## Steps

1. Start the orders service's `buildServer(neighbours, new OrderBook())` with stub neighbours (no network needed; `app.inject`).
2. `GET /orders/o-999` on an empty book: answers 404 (control).
3. `POST /orders/o-999/pay`, then `/ship`, then `/cancel`.
4. Read the order count of the book: still 0.

## What differs

Expected: any request that names an order that does not exist answers 404 and changes nothing (rule "Unknown order not found", whose unwanted condition is "a request names an order that does not exist", so it is not limited to GET).
Actual: `GET` answers 404 as expected, but `pay`, `ship` and `cancel` each answer 500 with "Cannot read properties of undefined (reading 'status')". The book is unchanged (0 orders) in every case, so the damage is only the wrong status and an error in the log.
Seen: 2 of 2
Where it probably comes from: services/orders/src/orderBook.ts:34 (`const order = this.orders.get(id)!`: the non-null assertion hides the missing order, and `order.status` at :35 throws); the move routes in services/orders/src/server.ts:54-62 do not catch it, since they only map `WrongMove` to 409.
A test that would catch it: services/orders/test/orders.test.ts › orders › answers 404 to an unknown order. It asserts only the GET route; it should also POST `/orders/:id/pay`, `/ship` and `/cancel` for an unknown id and expect 404 with no order changed.
