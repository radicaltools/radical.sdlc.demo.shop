## Steps

1. POST http://localhost:4703/events {type:'order.paid', orderId:'o-A'} with no id
2. POST http://localhost:4703/events {type:'order.shipped', orderId:'o-B'} with no id
3. GET /notifications?orderId=o-B

## What differs

```text
Expected: the second event is refused with a 4xx, or recorded for o-B
Actual: the second is answered {orderId:'o-A', text:'Your payment arrived.'}; the list for o-B is []
Seen: 2 of 2
Where it probably comes from: services/notifications/src/notifier.ts handle(), the Map keyed on event.id (line 17 and 20) (guess: no check that id is present)
A test that would catch it: services/notifications/test: an event without an id is refused with a 4xx; two different events without ids are each recorded for their own order
```
