## Steps

1. Start the pricing service's `buildServer()` (no network needed; `app.inject`).
2. `POST /quote` with one line `{ sku: 'mug', unitPrice: 20, quantity: 1 }` and `code: 'constructor'`.
3. Same with `code: 'toString'`.
4. Same with `code: 'NOPE'` as a control.

## What differs

Expected: an unknown code is refused with 400 and nothing is priced (rule "Unknown code refused").
Actual: `constructor` and `toString` answer 200 with `discount`, `vat`, `beforeShipping` and `total` all `null` (NaN serialised). The lookup `CODES[code]` reads the inherited `Object.prototype` members, so they count as known codes with no `share` or `cap`. `NOPE` is refused correctly with 400.
Seen: 2 of 2
Where it probably comes from: services/pricing/src/quote.ts:35 (`const rule = CODES[code]`; the table is a plain object, see :9)
A test that would catch it: services/pricing/test/quote.test.ts › quote › refuses an unknown code. It asserts only a made-up code such as "NOPE"; it should also assert that `constructor` and `toString` throw `UnknownCode` (or use a `Map` / `Object.hasOwn` for the lookup).
